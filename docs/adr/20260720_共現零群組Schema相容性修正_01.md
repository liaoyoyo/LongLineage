# ADR：共現零群組 Schema 相容性修正

## 狀態與決策

狀態：Accepted，2026-07-20。

將 `group_allele_counts` 與 `cooccurrence_pairs` 由 1.0.0 增補為
1.0.1。1.0.1 接受 0–10 個 group；空陣列只表示該 pair 沒有任何
R/A-informative M1 group。舊 1.0.0 檔案及 SHA 保留不變，v3 失敗 run
不修改 receipt、不 freeze；修復後使用新 run ID 全量重產。

## 問題與證據

HCC1395 v3 producer 正常產生 134,278 個 pair。獨立 validator 在
`cooccurrence_pairs` data row 433（1-based）拒絕
`group_allele_counts_json=[]`：舊 embedded schema 要求 `minItems=1`。
全量共有 11 筆同類 tail case，皆同時滿足：

- `group_count=0`
- `n_informative=min_group_n=ref_n=alt_n=0`
- `exact_status=NOT_IDENTIFIABLE_ENDPOINT_A_NOT_TESTABLE`
- `family_status=INELIGIBLE_M2_SCREEN`

producer 與獨立 science replay 都把「無 R/A group」定義為空矩陣；
array-length、matrix total、column total、minimum 及 canonical SHA
守恆也都能在空矩陣上明確計算為 0。因此這是 stale schema，不是壞資料。

## 被否決的替代方案

1. 捏造 `[0,0]` group：會把不存在的 M1 group 寫入結果，破壞
   `array length == group_count` 與科學 grain。
2. 刪除 11 個 pair：會改變 frozen ±5 kb pair universe。
3. validator 對舊 schema 特判：會繞過 receipt 鎖定的 catalog/SHA，
   使 fail-closed provenance 失效。
4. 直接修改 1.0.0：違反歷史 schema 不覆寫原則，且使 v3 無法依原契約
   重播。

## 相容性與不變量

1.0.1 是 bug-fix widening：所有 1.0.0 合法非空矩陣仍合法。下列限制
保持不變：

- 最多 10 個 group。
- 每個非空 row 恰有兩個非負 `uint32` cells：`[REF, ALT]`。
- array length 等於 `group_count`。
- matrix total、column total、minimum row total 與欄位一致。
- canonical JSON SHA-256 必須一致。

producer 的 pair 科學計算、pair universe、FDR family、status precedence
及 topology gate 均不改；只有 artifact schema identity 由 1.0.0 改為
1.0.1。

## Step → Verify

1. 保留 1.0.0 並新增 1.0.1 schema
   → 驗證：舊兩檔 SHA 仍為 `ac292f…`、`42fc9a…`。
2. 更新 catalog、ID registry、contract registry 與 producer metadata
   → 驗證：所有 physical hash replay 與 schema fixture PASS。
3. 新增 `[]` positive fixture，保留 malformed K×2 negative fixture
   → 驗證：`scripts/ci/check_json_schema_fixtures.sh` exit 0。
4. 新 run ID 全量重產並由獨立 validator freeze
   → 驗證：11 個空矩陣通過，scientific conservation 全 PASS。
5. 以不同 worker 數重跑
   → 驗證：production semantic SHA-256 完全一致。
