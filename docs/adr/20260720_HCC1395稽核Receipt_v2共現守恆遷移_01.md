# ADR：HCC1395 稽核 Receipt v2 共現守恆遷移

- 狀態：Accepted
- 類型：E — integration contract hotfix
- 服務目標：LL-G2、LL-G4、LL-G5
- Claim ceiling：只證明 frozen HCC1395 science artifacts 的 deterministic census、守恆與歷史可比性邊界，不宣稱真實 clone、ancestry、時間順序或唯一演化樹。

## 決策

`longlineage.hcc1395_determinism_historical_receipt` 的 current contract 直接升為
`2.0.0`。舊 `1.0.0` schema 以 immutable snapshot 保留；不發布中間
`1.1.0` receipt contract。

current schema：

`schema/core/hcc1395_determinism_historical_receipt.schema.json`

v1 snapshot：

`schema/core/hcc1395_determinism_historical_receipt-1.0.0.schema.json`

snapshot 必須與 migration 前的 HEAD blob byte-identical，固定 SHA-256：

`5f346604954cdffae26cba79a05de165289af7416c8d23990677b0e4cc8e60f2`

## 為何是 breaking major

v1 receipt 有七個 audit checks，`determinism` 不要求
`cooccurrence_replay`。v2 同時做了以下不相容變更：

1. checks 由 7 筆改為固定 8 筆。
2. 第七筆新增
   `COOCCURRENCE_SERIALIZED_CENSUS_CONSERVATION`。
3. 八筆 check 的位置改由 Draft 2020-12 `prefixItems` 固定，不再只驗集合。
4. `determinism.cooccurrence_replay` 成為 required object。
5. 新增 pair family、exact-identifiability、BH/BY/formal discovery、
   pair/site aggregate、joint-signature 與 topology-unit counters。
6. 新增 family partition、subset hierarchy、跨 artifact 與 w24/w40
   worker-invariance 守恆。

舊 receipt 缺少 required object 與第八個 check，無法在不重跑 audit 的情況下
成為 v2 receipt。這不是 backward-compatible additive minor，因此
`1.1.0` 會錯誤暗示相容性；正確版本是 `2.0.0`。

## 版本與相容性矩陣

| Instance | v1 snapshot | current v2 | current HTML consumer |
|---|---:|---:|---:|
| synthetic v1 receipt：version 1.0.0、7 checks、無 cooccurrence replay | PASS | REJECT | REJECT |
| C++ 新產生 v2 receipt：version 2.0.0、固定 8 checks、完整 replay | REJECT | PASS | PASS |
| v2 receipt 交換前兩個 checks | REJECT | REJECT | REJECT |

v1 snapshot 只用於重播歷史 receipt 的原始契約，不代表 v1 可進入 current report。
current consumer fail closed，只接受 `schema_version=2.0.0`。

## Rerun migration

禁止直接編輯舊 receipt 把版本字串改成 `2.0.0`。正確遷移如下：

1. 保留舊 receipt 與其原始 provenance。
   → 驗證：舊 synthetic fixture 只通過 v1 snapshot。
2. 對相同的兩個 `VALIDATED_FROZEN_DATASET_GATE` w24/w40 roots、manifest 與
   historical M1 authority 重新執行 C++ audit。
   → 驗證：新 receipt 由 v2 audit executable 產生，含固定 8 checks 與
   `cooccurrence_replay`。
3. 用 Draft 2020-12 validator 驗證新 receipt。
   → 驗證：v2 errors 為 0；交換任兩個固定 check 後 errors 大於 0。
4. 重建 execution evidence，綁定新的 audit executable、source commit、
   receipt、CTest log 與 physical SHA-256。
   → 驗證：validated-only Python consumer 接受 v2，拒絕 v1。
5. 重新產生 HTML/JSON；不得沿用舊 report receipt。
   → 驗證：輸出只呈現 C++ receipt counters，不讀 scientific artifact data
   rows，也不重算 science。

這項遷移不修改 frozen v6 science artifacts；它只重建 audit/report
provenance。`tests/fixtures/hcc1395_audit/verification_receipt.json` 仍綁舊
source commit 與舊 case set，不能在 dirty worktree 內覆寫。必須等 final
integration commit 後另建 superseding receipt。

## Synthetic verification receipt 的 A → B provenance

舊 `tests/fixtures/hcc1395_audit/verification_receipt.json` 保持 immutable。
它只覆蓋 18 個 cases、舊 source commit 與不支援 `prefixItems` 的
`jsonschema 3.2.0`，不能直接編輯成 current evidence。

current superseding receipt 由
`schema/core/hcc1395_audit_verification_receipt.schema.json` 封閉驗證，
採兩個 commit：

1. **Commit A** 只含 implementation、tests、science receipt v1/v2
   schemas、verification schema、builder、ADR 與 living notes。
   → 驗證：在 clean detached checkout A 重新執行固定 12 項 validations；
   receipt 的 verified source commit、source snapshot 與 binary embedded
   commit 全部只指向 A。
2. **Commit B** 只加入
   `tests/fixtures/hcc1395_audit/verification_receipt_v2.json`。
   → 驗證：tracked copy 與 repo 外預驗 copy 的 SHA-256 完全相同，且
   Draft 2020-12 positive/negative oracles 全部通過。

receipt 不保存自己的 SHA、未來 commit B 或 `included_by_commit`，避免
self-reference cycle。B 的 fresh binary 可因 embedded Git commit 而與 A
binary 不同；正式 HCC1395 real-data audit 必須另以 B binary/execution
evidence 綁定，不可拿 synthetic A receipt 冒充正式 science run receipt。

## Backward-negative 與固定順序驗證

schema migration oracle 使用 synthetic v2 receipt，建立一份 synthetic v1
fixture：把 `schema_version` 改回 `1.0.0`、移除
`determinism.cooccurrence_replay`，並移除
`COOCCURRENCE_SERIALIZED_CENSUS_CONSERVATION` check。驗收必須同時證明：

- v1 fixture 通過 byte-identical v1 snapshot。
- 同一 v1 fixture 被 current v2 schema 拒絕。
- 原始 v2 receipt 通過 current v2 schema。
- 交換 v2 checks[0] 與 checks[1] 後，被 current v2 schema 拒絕，錯誤位置包含
  `checks/0/check_id` 與 `checks/1/check_id`。
- C++ positive unit 明確 assert receipt version 為 `2.0.0`。
- Python self-test 包含 `audit_receipt_v1_rejected`，current consumer 對 v1
  fail closed。

validator 必須是 `jsonschema==4.23.0` 的
`Draft202012Validator`。系統 `/usr/bin/jsonschema` 3.2.0 只會以 Draft 7
fallback，無法辨識 `prefixItems`，因此不得作為 migration 或 check-order
證據。

## 為何不改 catalog 與 id_registry

這份 receipt 是獨立 audit/report evidence，不是
`schema/catalog.json` 的 production run science artifact，也不在
`run_membership.scientific_artifact_ids` 或 artifact catalog rows 中。v1
schema 原先也未登錄於 `schema/id_registry.json`。

本 hotfix 以明確 `$id`、current schema path 與 immutable v1 snapshot
完成版本分流。此時修改 catalog 或 id_registry 會把 audit-only evidence
誤耦合進 production artifact registry，並造成無關 catalog digest 與
production provenance churn。因此本 ADR 明確決定兩者不變；若未來要把 audit
receipts 納入通用 registry，必須另立 ADR、定義 artifact role、producer、
validator、query support 與 migration。

## 驗收命令

```bash
sha256sum \
  schema/core/hcc1395_determinism_historical_receipt-1.0.0.schema.json

LONGLINEAGE_AUDIT_TEST_RECEIPT=/tmp/longlineage-audit-positive-v2-migration.json \
  build-cooccurrence-counters/bin/test_hcc1395_audit

PYTHONDONTWRITEBYTECODE=1 \
  python3 presentation/build_hcc1395_validated_report.py --self-test

python3 -m pip install --target /tmp/longlineage-jsonschema4 \
  'jsonschema==4.23.0'

PYTHONPATH=/tmp/longlineage-jsonschema4 python3 - <<'PY'
import copy
import json
from importlib.metadata import version
from jsonschema import Draft202012Validator

assert version("jsonschema") == "4.23.0"
with open(
    "schema/core/hcc1395_determinism_historical_receipt-1.0.0.schema.json"
) as handle:
    v1_schema = json.load(handle)
with open(
    "schema/core/hcc1395_determinism_historical_receipt.schema.json"
) as handle:
    v2_schema = json.load(handle)
with open("/tmp/longlineage-audit-positive-v2-migration.json") as handle:
    v2_receipt = json.load(handle)

v1_fixture = copy.deepcopy(v2_receipt)
v1_fixture["schema_version"] = "1.0.0"
v1_fixture["determinism"].pop("cooccurrence_replay")
v1_fixture["checks"] = [
    row
    for row in v1_fixture["checks"]
    if row["check_id"] != "COOCCURRENCE_SERIALIZED_CENSUS_CONSERVATION"
]
swapped = copy.deepcopy(v2_receipt)
swapped["checks"][0], swapped["checks"][1] = (
    swapped["checks"][1],
    swapped["checks"][0],
)

v1 = Draft202012Validator(v1_schema)
v2 = Draft202012Validator(v2_schema)
old_v1 = list(v1.iter_errors(v1_fixture))
old_v2 = list(v2.iter_errors(v1_fixture))
new_v1 = list(v1.iter_errors(v2_receipt))
new_v2 = list(v2.iter_errors(v2_receipt))
swapped_v2 = list(v2.iter_errors(swapped))
print(
    f"old_v1_errors={len(old_v1)} old_v2_errors={len(old_v2)} "
    f"new_v1_errors={len(new_v1)} new_v2_errors={len(new_v2)} "
    f"swapped_v2_errors={len(swapped_v2)}"
)
print(
    "swapped_paths="
    + ",".join("/".join(map(str, error.absolute_path)) for error in swapped_v2)
)
assert not old_v1 and old_v2 and new_v1 and not new_v2 and swapped_v2
PY

ctest --test-dir build-cooccurrence-counters --output-on-failure
```

最後一個 schema oracle 必須輸出 validator version、四項 PASS/REJECT
矩陣與 swapped error paths；只報 CLI exit code 不足以證明 Draft 2020-12
語意。
