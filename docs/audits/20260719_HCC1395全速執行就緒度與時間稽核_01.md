`INPUT_LOCK_PREFLIGHT → BLOCK_PLAN → HTS_READ_JOIN_PROJECT → MM_ML_DECODE →`
`M1 → M2_ELIGIBILITY → COOCCURRENCE → TOPOLOGY_OBJECTIVE →`

`INDEPENDENT_VALIDATE → ATOMIC_FREEZE → REPORT_BUNDLE`

records/bytes、queue/reorder wait與task latency。重疊 spans以parent/span ID

## 結論

此輪正確動作是**不啟動長 run**：即使恢復big8，現有程式仍會在release
attestation或engine stub處fail closed，無科學輸出；若先做大量full SHA，
只會浪費序列I/O。先完成bounded authority、P2 production bundle、P3–P6與
C++ performance/report bundle，再恢復mount並啟動HCC1395 40-worker
profiling，才能第一次得到可信的逐步時間與真正的production HTML時間。
