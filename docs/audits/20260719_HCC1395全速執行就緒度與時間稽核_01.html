06 · Bottleneck ranking

先解鎖正確性與可執行性，再談 CPU 加速

01
BLOCKER

流程本身尚未存在

The current producer always returns KernelBlocked even after preflight; M1, M2, full topology, validator and report bundle are not release-enabled.

解鎖：Complete and independently verify P2 through P6 before any full-data timing.

02
BLOCKER

資料 mount 缺失

<BIG8_INPUT> is an empty local directory in this session, not the frozen NFS mount.

解鎖：Restore the exact mount and re-verify BAM/BAI/FASTA/FAI identities before preflight.

03
BLOCKER

HCC1395-only 與 production authority 衝突

The production CLI accepts only the exact seven-dataset profile; a one-dataset run is rejected.

解鎖：Add a governed BOUNDED_REAL_DATA benchmark profile that stays PARTIAL and cannot be promoted to production evidence.

04
HIGH

序列 I/O 與 full hashing

Preflight recomputes complete SHA-256 per locked file and scans indexed records; with a 292.06 GB BAM this can dominate before science starts.

解鎖：Measure per-stage I/O with C++ /proc/self/io and getrusage; never skip identity checks for speed.

05
HIGH

舊輸出的小檔案爆量

The legacy HCC1395 extractor produced at least 239,061 site-level files across three artifact families.

解鎖：Use streamed BGZF native artifacts and indexes; do not recreate per-site directory trees.

06
HIGH

記憶體與 transient storage 尚無物理上限證據

Current P2 accounting covers logical retained payload only; HTSlib buffers, allocator overhead, thread stacks and transient files are not bounded.

解鎖：Implement a process-wide permit budget, RSS sampler and transient-space/inode preflight.
